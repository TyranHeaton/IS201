What I did at FamilySearch

Here is an image of a historical record

For decades, people have read records like this and manually captured key details such as record type, names, location, and date. With tens of billions of records at FamilySearch, the process is time‑intensive at human scale. My role was to build AI‑driven software that automatically extracts information like this.

To achieve this, I used large language models (LLMs) and machine learning. The code is proprietary to FamilySearch, so I can’t share it, but I can provide pseudocode to illustrate the approach, as follows:

Image-to-Metadata AI Pipeline: Step by Step

  1. A Request Arrives: A request is sent to our application server to analyze an image and extract the needed metadata.
  2. Prediction Request Handling:
    • If the request is for an LLM to extract data from an image, the server identifies the correct AI model (specified in the request).
    • It gathers all attached files, such as the image itself, transcripts, and any supporting metadata to improve extraction accuracy.
    • It reads and validates the file contents.
    • It composes a prompt that combines the image data and contextual metadata for the AI model.
    The Predict Method
    When a POST request arrives at /predict:
- Extract the model name from request parameters or form data
  (default: "gpt-4.1")
- If model is missing:
  - Return error response
- Extract files from the request:
  - image_file: the image to analyze (required)
  - transcript_file: text transcript (optional)
  - metadata_file: metadata (optional)
  - entities_file: identified entities (optional)
- Read contents of each file (decode as UTF-8 text)
- Format the user prompt using transcript, metadata, and entities
- Create an AI Broker Client instance
- Try:
  - If model starts with "gpt":
    - Prepare image file tuple (filename, bytes, mimetype)
    - Call openai_extract_data with image, model, system
      prompt, user prompt
  - Else if model starts with "gemini":
    - Prepare image file tuple
    - Call gemini_extract_data with image, model, system
      prompt, user prompt
  - Else if model starts with "us.anthropic.claude":
    - Prepare image file tuple
    - Call bedrock_extract_data with image, model, system
      prompt, user prompt
  - Else:
    - Return error for unknown model
- Catch any exceptions:
  - Log the error
  - Return error response
- If result contains error:
  - Return error response
- Return result as JSON response
  3. Contacting the AI Broker:
    • The server uses a helper (the AI Broker Client) to communicate with the AI Broker service.
    • Depending on the model chosen, it formats the data according to the AI model's expectations.
    • It sends the formatted data to the AI model and waits for a response.
    AI Model Extraction Methods
    Gemini Extraction Method
    To extract data using Gemini:
- Build the Gemini vision endpoint URL with the model name
- Create a payload:
  - "contents" is a list with two items:
    - First: system prompt as text
    - Second: user prompt as text
- Prepare files dictionary:
  - "payload": JSON-encoded payload
  - "file": image file tuple
- Send POST request to AI Broker with files
- Parse and return the extracted information from the response
    OpenAI Method
    To extract data using OpenAI:
- Build the OpenAI vision endpoint URL
- Create a payload:
  - "model": model name
  - "input": list with one item:
    - "role": "user"
    - "content": list with one item:
      - "type": "input_text"
      - "text": system prompt + user prompt
- Prepare files dictionary:
  - "payload": JSON-encoded payload
  - "file": image file tuple
- Send POST request to AI Broker with files
- Parse and return the extracted information from the response
    Bedrock Model Method
    To extract data using Bedrock:
- Build the Bedrock vision endpoint URL with the model name
- Create a prompt dictionary:
  - "anthropic_version": version string
  - "system": system prompt
  - "messages": list with one item:
    - "role": "user"
    - "content": list with one item:
      - "type": "text"
      - "text": user prompt
  - "max_tokens": 512
  - "top_p": 0.9
  - "stop_sequences": list of stop strings
- Prepare files dictionary:
  - "prompt": JSON-encoded prompt
  - "file": image file tuple
- Send POST request to AI Broker with files
- Parse and return the extracted information from the response
  4. Processing the AI's Response:
    • The server checks whether the AI broker returned an error.
    • If an error occurred, it sends back an error message to the client.
    • If successful, it organizes and structures the AI's results for further processing.
    Parsing Extracted Information Method
    To parse the AI Broker response:
- Search the response text for a particular text block formatting according to the prompt's instructions.
- If not found:
  - Raise error: no extracted information
- For each line in the extracted block:
  - If line contains ":" (key-value pair):
    - Split into key and value
    - If value contains "unknown", skip
    - Normalize key (lowercase, strip spaces)
    - If key matches known fields (record type, place, date, language):
      - Map to internal field name
      - Add to result dictionary
- Return the result dictionary
  5. Logging and Finishing Up:
    • The server logs the request duration, status, and other diagnostic details for monitoring and debugging purposes.

Testing and Results

For LLM testing, this process runs automatically on thousands of images at a time. Once an LLM completes extraction for large datasets, the results are tested against ground truth datasets and F-scores are calculated using pre-built testing suites. F-scores measure how accurately the models extracted data from images.

As shown in the chart below, the highest-scoring model achieved over 85% accuracy! As AI continues to improve and LLMs become more sophisticated, we're moving toward a future where manual record transcription may no longer be necessary.
